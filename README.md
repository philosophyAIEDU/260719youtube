# Philosophy AI 유튜브 분석 앱 · 브랜드 서사 진단

유튜브 채널을 **조회수·구독자**가 아니라 **“이 사람이 왜 이 채널을 시작했는가”라는 메시지와 서사**의
관점에서 분석하는 개인용 정적 웹 앱입니다. 한 번 보고 끝나는 리포트 도구가 아니라, **채널별로 분석
기록이 쌓이고 그 위에서 계속 상담을 이어갈 수 있는 AI 유튜브 컨설턴트**로 동작합니다. 서버·데이터베이스·
회원가입·광고가 전혀 없고, 모든 것(API 키, 분석 기록, 대화 내용)은 오직 사용자의 브라우저(localStorage)에만
저장됩니다.

## 실행 방법

별도 빌드가 필요 없습니다. `index.html` 을 브라우저에서 열면 됩니다.

1. 우측 상단 **⚙️ 설정** 에서 두 API 키 입력
   - **YouTube Data API 키** — [Google Cloud Console](https://console.cloud.google.com/) 에서 `YouTube Data API v3` 활성화 후 발급
   - **Gemini API 키** — [Google AI Studio](https://aistudio.google.com/app/apikey) 에서 무료 발급
2. 채널 주소/핸들 입력 후 **분석하기**
   - 지원 형식: `@핸들`, `youtube.com/@핸들`, `youtube.com/channel/UC...`, `youtube.com/user/...`, 채널명 검색

> 참고: 일부 브라우저는 `file://` 로 열 때 정적 자산 로딩을 막을 수 있습니다.
> 그럴 경우 이 폴더에서 `python3 -m http.server` 를 실행하고 `http://localhost:8000` 으로 접속하세요.

## 이 앱의 핵심 관점

일반적인 유튜브 분석 도구는 조회수를 성공의 기준으로 삼습니다. 이 앱은 다릅니다.

- **도달(조회수) 과 공명(참여율)을 분리**해서 봅니다. `(좋아요+댓글)/조회수` 가 높은 영상이
  메시지가 사람에게 실제로 가 닿은 영상일 가능성이 큽니다.
- Gemini 에게 보내는 프롬프트는 **자극적 주제/트렌드 편승/썸네일·SEO 팁을 명시적으로 금지**하고,
  창작자의 **‘왜(Why)’ · 메시지 일관성 · 서사 축적 · 차별성** 을 진단하도록 정성껏 설계되었습니다.
- **채널의 (사실상) 전체 영상 이력**을 페이지네이션으로 수집해 통계를 계산합니다(안전 상한 500개,
  `config.js`의 `MAX_VIDEOS_FETCH`). 초기/중기/최근 3구간 추이까지 반영해, 스냅샷이 아니라
  채널이 걸어온 궤적을 근거로 분석합니다.

## 신빙성(Credibility) 기능

AI 분석은 틀릴 수 있습니다. 이 앱은 결과를 맹신하지 않고 검증할 수 있도록 여러 장치를 둡니다.

- **데이터 출처 배너** — 몇 개를 수집했는지(전수/부분), 활동 기간, 분석 시각을 결과 상단에 명시합니다.
- **원본 데이터 투명 공개** — "AI가 참고한 원본 데이터 통계 보기"를 펼치면 Gemini에게 실제로 전달된
  통계 텍스트 원문을 그대로 볼 수 있습니다.
- **근거(evidence) 자동 대조 검증** — 핵심 메시지의 근거로 인용된 영상 제목을 실제 수집된 영상 목록과
  자동 대조해 ✓ 검증됨(해당 영상으로 링크) / AI 해석(대조 실패)으로 표시합니다.
- **AI 자체 재검증(감사)** — "🔎 결과 재검증" 버튼을 누르면 별도의 Gemini 호출이 방금 나온 스코어카드를
  원본 통계와 다시 대조해 과장·모순 여부를 스스로 감사하고, 통과/검토 필요 판정과 개별 체크리스트를 보여줍니다.

## 지속 상담 — AI 유튜브 컨설턴트

이 앱의 핵심 차별점입니다. 채널을 분석할 때마다 그 결과가 **채널별 기록으로 브라우저에 계속 쌓이고**,
다음에 다시 방문했을 때 그 기록 위에서 상담을 이어갈 수 있습니다.

- **📁 내 채널 상담 기록** — 메인 화면에 지금까지 분석한 채널이 카드로 표시됩니다. 채널마다
  **🔄 다시 분석**(YouTube+AI를 새로 호출해 최신 상태로 재분석) 과 **💬 상담 계속하기**(AI를 다시
  부르지 않고 저장된 마지막 분석 결과 + 대화 기록을 즉시 불러와 채팅부터 이어감 — 무료 한도 절약) 를
  선택할 수 있습니다.
- **지난 상담 대비 변화** — 같은 채널을 두 번째 이상 분석하면, 이전 점수 대비 변화(▲/▼, JS로 직접
  계산해 신뢰도 확보)와 AI가 서술하는 `trendNote`(무엇이 나아졌는지/제자리인지 근거와 함께)가 함께
  표시됩니다. 프롬프트에도 지난 상담 요약이 들어가, AI가 "지난번엔 이랬는데 이번엔…" 식으로 진전을
  평가합니다.
- **🕓 이 채널 상담 이력** — 결과 화면에서 지금까지의 모든 분석(날짜·점수·한줄평)을 펼쳐볼 수 있습니다.
- **채팅도 채널별로 영구 저장** — 결과 화면 우측 하단 **💬 이 채널에 대해 더 물어보기** 위젯에서 나눈
  대화는 채널별로 저장되어, 나중에 다시 방문해도 그 대화에 이어서 상담할 수 있습니다. 실제 채널 데이터 +
  최신 분석 결과 + 지난 상담 요약을 시스템 지침으로 그라운딩하므로, 제공되지 않은 사실은 지어내지 않고
  "데이터에 없어 답하기 어렵다"고 답하도록 설계되어 있습니다.

## 자막(스크립트) 분석 — 선택 기능, 본인 채널 전용

기본적으로 이 앱은 제목·설명글·참여 지표만 봅니다(영상 속 실제 발화 내용은 보지 않음). 검색창 아래
**🎙️ 내가 이 채널의 소유자라면, 자막까지 반영해 더 정확하게 분석하기** 체크박스를 켜면, 대표 샘플
영상 몇 개의 실제 자막을 가져와 "제목보다 신뢰도 높은 1차 근거"로 분석에 포함시킵니다.

- **왜 '본인 채널'만 되나요** — YouTube 공식 API(`captions.download`)는 로그인한 계정이 소유한
  채널의 자막만 내려줍니다. 다른 사람 채널 주소를 입력했을 때는 이 옵션을 켜도 자동으로 건너뛰고
  제목·설명 기반으로만 분석됩니다(에러 없이 조용히 폴백).
- **완전 opt-in** — 체크박스를 켜지 않으면 Google 로그인 스크립트조차 불러오지 않습니다. 체크 후
  분석을 누르면 그때 Google 로그인 창이 뜹니다. 액세스 토큰은 메모리에만 유지되고 저장되지 않습니다
  (새로고침하면 다시 로그인).
- **소유권 확인** — 로그인 직후 `channels.list?mine=true` 로 로그인한 계정의 채널 ID를 확인해,
  지금 분석 중인 채널과 일치할 때만 자막을 가져옵니다. 일치하지 않으면 안내 문구만 띄우고 정상적으로
  제목/설명 기반 분석을 계속합니다.
- **비용 보호** — `captions.list`(50단위) + `captions.download`(200단위)는 매우 비싼 API라
  대표 샘플 소수(기본 `TRANSCRIPT_MAX_VIDEOS = 5`)만 가져오고, 일반 분석/채팅과 **별도의, 더 엄격한**
  브라우저별 한도(`TRANSCRIPT_RATE_LIMIT`, 기본 시간당 1회·하루 3회)로 보호합니다.

### 설정 방법

OAuth 클라이언트 ID는 코드를 건드리지 않고 **화면에서 바로 입력**할 수 있습니다. 체크박스를 켜면
발급 방법을 단계별로 보여주는 안내가 함께 펼쳐지며, "승인된 자바스크립트 원본"에 등록해야 할 **현재
사이트 주소를 자동으로 표시**해주고 복사 버튼도 제공합니다(`file://` 로 열었을 때는 로컬 서버로
띄우라는 안내가 대신 표시됩니다).

1. 체크박스를 켜면 바로 아래에 발급 절차 안내와 "🔑 Google OAuth 클라이언트 ID" 입력란이 나타납니다.
2. YouTube 키를 만든 것과 **같은 Google Cloud 프로젝트**에서:
   - **API 및 서비스 → OAuth 동의 화면** 설정 (User Type: 외부, 테스트 사용자에 본인 계정 추가)
   - **API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션** → 승인된 자바스크립트 원본에 배포 주소 등록
     (예: `https://당신앱.netlify.app`, 로컬 테스트 시 `http://localhost:8000` 도 추가)
3. 발급된 `...apps.googleusercontent.com` 클라이언트 ID를 화면의 입력란에 붙여넣고 **저장**
   — 이 값은 비밀 키가 아니라 공개돼도 되는 식별자라 브라우저에 입력해도 안전하며, 이 브라우저의
   localStorage 에만 저장되고 이후에는 다시 입력할 필요가 없습니다.

배포자가 모든 방문자를 위해 미리 설정해두고 싶다면, `assets/js/config.js` 의 `GOOGLE_OAUTH_CLIENT_ID`
에 넣어두면 됩니다(방문자가 자기 것을 입력하면 그게 우선 사용됩니다). 아무 것도 설정하지 않아도
체크박스와 앱의 다른 모든 기능은 정상 동작하며, 자막 기능만 "입력해야 쓸 수 있는" 상태가 됩니다.

## 분석 모델

기본값은 **Gemini 3.5 Flash (`gemini-3.5-flash`)** 입니다. 설정(⚙️) 화면의 **분석 모델**
드롭다운에서 **Gemini 3.1 Flash Lite (`gemini-3.1-flash-lite`)** 로 바꿀 수 있습니다(더 빠르고
저렴하지만 분석 깊이가 다를 수 있음). 선택은 이 브라우저에 저장되며, 다음 분석부터 바로 적용됩니다.

선택한 모델이 API 에서 아직 노출되지 않아 404 가 날 경우에만 동일 계열 후보로 자동 대체하며, 실제로
응답한 모델은 결과 화면의 "종합 총평" 하단에 표시됩니다.

## 결과 화면 구성

프로페셔널 분석 대시보드 형태로, 정량 스코어카드를 중심에 둡니다. 섹션 번호는 조건부 섹션(방향성 상담)
유무에 따라 자동으로 매겨지므로, 아래 번호는 "영상이 적은 초기 단계 채널"을 분석했을 때 기준입니다.

| # | 섹션 | 내용 |
|---|---|---|
| 01 | **브랜드 서사 스코어카드** | 종합 점수(링 게이지·A~D 등급) + 5개 지표(메시지 선명도·일관성·서사 축적력·차별성·오디언스 공명)를 0~100점 바로 시각화. 지표마다 진단과 "이 점수를 올리려면" 제안 포함 |
| 02 | 핵심 메시지 | 이 채널을 왜 시작했는지 추론 + 근거 |
| 03 | **방향성 상담** *(초기 단계 채널만)* | 영상이 `LOW_VIDEO_THRESHOLD`(기본 5개) 이하면 자동 등장. 패턴 단정 대신 방향성 가설·시도해볼 실험·다음에 확인할 것을 제시 |
| 04 | 포지셔닝 & 슬로건 | 한 문장 포지셔닝 + 브랜드 슬로건 후보 3개 |
| 05 | **우선순위 액션** | 가장 낮은 점수부터 보완하는 실행안(우선순위·대상 지표·이유·방법) |
| 06 | **90일 브랜딩 로드맵** | 0~30 / 30~60 / 60~90일 단계별 목표와 행동 |
| 07 | 콘텐츠 기둥 | 이 채널이 소유해야 할 콘텐츠 축 3~4개 |
| 08 | 주제 태그 | 핵심 주제 3~5개 |
| 09 | 콘텐츠 리뷰 | 지금까지 콘텐츠를 브랜드 관점에서 패턴별 리뷰 |
| 10 | 공명 분석 | 어떤 유형의 영상이 마음에 가 닿았는지 (조회수 나열 아님) |
| 11 | **채널 소개글 리라이트** | 현재 소개글 → 메시지가 선명한 제안본 (Before/After) |
| 12 | 다음 영상 제안 | 서사를 확장하는 제목 후보 + 서사 기여 설명 |
| 13 | **수익화 컨설팅** | 채널의 메시지·니치·오디언스·현재 규모에 맞는 수익화 방법 3~5개(적합도·이유·시작 방법·브랜드 훼손 위험까지) |
| 14 | **영상 데이터 전수 분석** | 채널의 (사실상) 전체 영상을 제목·업로드일·조회수·좋아요·댓글·**참여율**로 정리. 모든 열 정렬 가능, 페이지네이션(기본 25개/페이지) |
| 15 | 종합 총평 | 채널의 서사적 정체성과 방향 |

상단에서 **📋 리포트 복사(Markdown)** 와 **🖨️ 인쇄/PDF** 가 가능하고, 결과 화면에는 데이터 출처 배너 ·
원본 데이터 투명 공개 패널 · AI 재검증 버튼이 함께 표시되며, 우측 하단에는 후속 질문 채팅 위젯이 뜹니다.

### 영상이 적은 초기 채널을 위한 컨설팅

패턴을 판단할 데이터가 없을 때 억지로 결론을 만들지 않도록, 영상 수가 적으면(기본 5개 이하)
프롬프트가 자동으로 "패턴 단정" 모드에서 "방향 탐색" 모드로 전환됩니다: 서사 축적력 등은 냉정하게
낮게 매기되 비판이 아니라 "아직 판단하기 이른 단계"로 설명하고, 우선순위 액션·로드맵도 "고쳐라"가
아니라 "처음 시도해보라"는 톤으로 바뀝니다. 후속 채팅에서도 같은 톤(가설과 다음 실험 제안)이 유지됩니다.

### 수익화 컨설팅

채널 규모와 무관하게 항상 포함됩니다. 광고 수익·브랜드 협찬·멤버십/슈퍼챗·디지털 상품·강의/컨설팅·
제휴 마케팅 중 이 채널의 메시지·니치·오디언스에 실제로 맞는 것만 제안하며, 지금 규모에서 비현실적인
방법(예: 구독자 100명인데 대형 브랜드 협찬)은 배제합니다. 채널의 진정성을 해칠 수 있는 방법은 `risk`
필드로 명시하고 적합도를 낮게 매깁니다 — 돈이 된다고 다 추천하지 않습니다.

## 공용(내장) 키로 배포하기 — 방문자가 키 없이 쓰게 하려면

방문자마다 API 키를 발급받게 하지 않고, **운영자의 무료 티어 키를 내장**해 바로 쓰게 할 수 있습니다.
`assets/js/config.js` 상단의 두 값을 채우세요.

```js
BUILTIN_YT_KEY: "AIzaSy...",  // 제한 걸린 YouTube 무료 키
BUILTIN_GM_KEY: "AIzaSy...",  // 제한 걸린 Gemini 무료 키
```

우선순위는 **사용자 입력 키 > 내장 키** 입니다. 방문자가 설정에서 본인 키를 넣으면 그 키가 쓰이고,
비워두면 내장 키가 쓰입니다.

### ‼️ 내장 키는 반드시 '제한'을 걸어야 안전합니다
클라이언트 앱에서는 키가 공개되므로(소스보기), 노출돼도 악용되지 못하게 Google Cloud Console 에서:

- **YouTube 키** — 애플리케이션 제한: HTTP 리퍼러 `당신앱.netlify.app/*` + API 제한: `YouTube Data API v3`
- **Gemini 키** — API 제한: `Generative Language API`
- **두 프로젝트 모두 결제(빌링) 연결 안 함** → 무료 한도를 넘어도 요금이 청구되지 않고
  그냥 멈췄다가 다음 날 초기화됩니다.

### 무료 한도 보호 (2중 구조)
서버가 없어 '전체 사용량 합산'은 불가능하므로 다음 2중 장치로 보호합니다.

1. **브라우저별 사용 제한** (`config.js`의 `RATE_LIMIT`, 기본 시간당 8회·하루 25회) —
   한 방문자가 공용 키를 통째로 태우지 못하게 막습니다. (본인 키 입력 시에는 제한 없음)
2. **무료 한도 소진 시 자동 정지** — YouTube 403 / Gemini 429 를 감지하면 재시도하지 않고
   "오늘 무료 한도 소진, 내일 초기화" 안내를 띄우고 멈춥니다.

## 보안 / 개인정보

- 사용자가 입력한 키는 브라우저 localStorage 에만 저장되며 외부 서버로 전송하지 않습니다.
- 모든 API 호출은 브라우저에서 Google API 로 직접 이루어집니다(순수 클라이언트 사이드).
- 내장 공용 키를 쓸 경우, 위의 '제한' 설정으로 보호하는 것을 전제로 합니다.
